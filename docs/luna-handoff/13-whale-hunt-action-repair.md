## 2. Interaction decisions

Hunt keeps the current server-owned two-location target payload until a versioned single-target scoring rule is introduced. The UI now treats one location as the tracer’s lead suspect and keeps the second location as a supporting compatibility field for the existing final scorer. This gives the player one clear decision per round without silently changing historical match semantics.

Synthetic fixtures remain explicitly synthetic. When a verified provider compilation supplies asset metadata, the reveal displays its symbol and name; pre-reveal screens continue to show Mystery aliases so the game does not leak the answer. Public metrics are calculated from the compiled historical candles and trades, whether the source is a fixture or a verified provider.

## 3. Verification sequence

1. Add focused contract and engine coverage for public metrics, reveal identities, scoped scans, and the shortened phase clock.
2. Implement the Hunt board, inspector, evidence lanes, lead suspect flow, phase feedback, and reveal scoreboard.
3. Run formatting, typecheck, unit/API tests, and the focused Hunt browser journey at desktop and mobile widths.
4. Update the Hunt wiki and module READMEs with current functions and line references.
